# VK-41 SHRIKE — Blender weapon build report

Original compact science-fiction rifle prop for Voxel Blitz, authored as real
3D geometry in Blender 5.2.1 LTS. Nothing here is a renamed or recoloured
KESTREL, and no downloaded model is used; every part is generated by
`build-shrike.py` from closed convex primitives.

| Delivery export | `public/assets/blender/omp-weapon/weapon.glb` | 2,640,232 B |
| Machine-readable record | `docs/design/blender/omp-weapon/manifest.json` | 3,118 B |
| Reimport evidence | `docs/design/blender/omp-weapon/validation.json` | 31,906 B |

Authoring script: `tools/blender/omp-weapon/build-shrike.py`.
Tooling: `render-views.py` (studio review renders), `validate-glb.py`
(independent GLB reimport checker), both in the same directory.

GLB SHA-256 prefix `59e66f25df1e2dff` — byte-identical across repeated builds,
so the export is deterministic.

## Design intent

The identity is an **open truss receiver**. A lower chassis and an upper spar
run the length of the gun and are joined by only three members — a rear brace,
a mid brace and the magwell cage — which leaves one long see-through window
with the magazine hanging inside the cage. The chassis then rises diagonally
into the spar at the front, so the receiver closes in one clean line instead of
trailing off into a slab.

Around that spine:

- **Magazine vs grip contrast.** The grip is a short, wide, raked plank with
  finger grooves on its front strap and a palm swell. The magazine is the
  opposite proportion: a deep, narrow box that drops far below the grip, with
  three vertical stiffening ribs, an orange witness stripe and a flared floor
  plate. At silhouette size the two hanging forms cannot be confused.
- **Low aperture yoke,** not a box optic. Two slim posts carry an octagonal
  aperture whose centre is exactly on the sight line, open on both sides, under
  a thin bridge. The sight window is unobstructed and the housing never rises
  above the aperture.
- **Wire-frame stock** with a genuine open triangle between two rods, a rear
  stanchion, a QD socket, a thin cheek pad and a compact sling wrap — nothing
  dangling.
- **Restrained mechanical detail** that reads at gameplay distance: a split top
  rail with lugs, a ground ejection port with a recessed bolt face, a left-side
  charging handle, a readout slot, heat ribs on the exposed bore, shroud vents,
  a handstop and modelled `SHRIKE` / `VB / 41` markings (geometry, not a decal).
- **Six real ImageGen maps**, each used where it is plausible: worn gunmetal for
  receiver, barrel, bolt and stock; petrol ballistic fabric for the support
  sleeve, cheek pad, grip patch and side inserts; tan webbing for the sling
  wrap; worn rubber for grip, butt pad, handstop face, vents and port; ivory
  coating for the spar coating band, optic chip and markings; chipped orange
  paint for muzzle ring, magazine plate and stripe, selector, release and
  latch.

## Geometry, material and texture counts

| Measure | Value |
| --- | --- |
| Authored source parts | 92 |
| Top-level nodes in the GLB | 9 (5 animation owners + 4 mount markers) |
| Merged meshes / draw primitives | 17 |
| Triangles | 12,832 |
| Materials | 8 |
| Embedded images | 6 (1024x1024 JPEG) |
| Texture payload | 1,762,868 B (identical byte sizes to the delivered copies) |
| Geometry + JSON payload | 877,364 B |

Budget: target was roughly 8k–20k triangles and ≤24 material draw batches —
12,832 triangles in 17 primitives is inside both. `body` 10,656 triangles,
`factory-optic` 744, `mag` 780, `bolt` 436, `trigger` 216.

Texture maps stay byte-identical to `public/assets/blender/textures/*.jpg`; the
exporter embeds them without re-encoding, and the original PNGs under
`docs/design/blender/textures/` are untouched. Every material samples its map
through an analytic per-face UV projection at a constant 4 tiles per metre, so
UVs exist on all 17 meshes (`mesh_count_with_zero_uv_layers: 0`) and the maps
tile at a fixed real-world density instead of being stretched per part.

Metalness is deliberately moderate (gunmetal 0.35, orange 0.12, ivory 0.04;
dielectrics 0.0). The runtime scene has no environment map, and a high-metalness
material with no image-based lighting renders black in three.js. The values above
keep the alkyd response readable under the game's own lights, which the browser
check demonstrates. Tints (gunmetal 0.86/0.87/0.89, rubber 0.62/0.63/0.65)
multiply the maps so the dark charcoal and pebbled rubber keep their character
instead of being flooded by studio specular.

## Axes

Authoring is Blender-native: **+Y forward (barrel), +Z up, +X right**. glTF
export applies the standard Y-up conversion, giving the runtime convention
**-Z forward, +Y up, +X right**. Model space relates to game-local space by

```
game_x = x,   game_y = z,   game_z = -y
```

Measured model extent, then the same inside the browser loader:

| Axis | Blender authoring | Game-local (glTF) |
| --- | --- | --- |
| across (x) | -0.0660 .. +0.0500 | -0.0660 .. +0.0500 |
| up | -0.2157 .. +0.1760 | -0.2157 .. +0.1760 |
| forward | -0.4359 .. +0.5980 | -0.5980 (muzzle) .. +0.4359 (butt) |

## Anchors

Modelled around the runtime contract, not just marked with empties. The bore
axis sits at x = -0.012, z = 0.045; the exposed barrel runs 0.520 .. 0.575 with
the shroud covering 0.300 .. 0.520; the breech point (0.320) is inside the
receiver.

| Marker | Contract | Measured in exported GLB |
| --- | --- | --- |
| `muzzle` | -0.012, 0.045, -0.598 | -0.012, 0.045, -0.598 |
| `grip` | 0.045, 0.015, -0.090 | 0.045, 0.015, -0.090 |
| `support` | -0.055, 0.005, -0.400 | -0.055, 0.005, -0.400 |
| `sight` | height 0.145 | 0.000, 0.145, -0.187 (aperture centre) |

The forward-most vertex of the whole model is exactly y = 0.5980, so the brake
tip lands on `TIMERS.rifle.muzzle` rather than near it. Animation owners are
top-level nodes `body`, `mag`, `bolt`, `trigger`, `factory-optic`; `mag`,
`bolt` and `trigger` hold only their own parts so the existing reload, bolt and
trigger controllers can drive them.

## Commands

```sh
# Author: creates the scene, packs textures, saves the .blend, exports the GLB
blender --background --factory-startup --python tools/blender/omp-weapon/build-shrike.py

# Review renders straight from the saved model
OMPW_SAMPLES=64 OMPW_FORCE_CPU=1 blender --background \
  docs/design/blender/omp-weapon/weapon.blend \
  --python tools/blender/omp-weapon/render-views.py

# Independent reimport check of the delivered GLB
blender --background --factory-startup --python tools/blender/omp-weapon/validate-glb.py \
  -- public/assets/blender/omp-weapon/weapon.glb \
  docs/design/blender/omp-weapon/validation.json

# End-to-end check through the repository's own GLTFLoader
python3 -m http.server 8099 --bind 127.0.0.1
# then open http://127.0.0.1:8099/docs/design/blender/omp-weapon/browser-check.html
```

The build always starts from empty factory settings and never opens, resets or
saves over an existing study; `render-views.py` builds its studio inside a new
temporary scene and does not save any `.blend`.

## Checks actually executed (tested, not assumed)

1. **Anchor contract assertions, at build time.** Muzzle tip position, all four
   markers and the 0.145 sight line are asserted against the contract on every
   build; output reads `anchor contract: all assertions pass`. A muzzle overshoot
   (the bore recess reaching 1.5 mm past the tip) was caught by this and fixed.
2. **Coplanar-face audit, at build time.** Flush faces between parts are
   rejected because same-material parts merge into one draw call, where flush
   faces z-fight and the seam crawls in game as well as in renders. The audit
   found and fixed 44 such planes, including a duplicated side panel: `mirror=True`
   on a shape centred on x=0 stacked an identical twin in the same volume. Output
   now reads `coplanar face audit: clean`.
3. **GLB reimport in a fresh Blender scene** (`validation.json`): 26 objects
   (17 meshes, 9 non-mesh), 12,832 triangles, 8 materials, 6 embedded images,
   0 meshes without UV layers, all nine expected node names present, no duplicate
   top-level names, no non-finite coordinates, no non-positive scales.
4. **Browser load through the repository's own `GLTFLoader` 0.180.0**
   (`browser-check.html`, verified in headless Chromium): loads and renders the
   GLB in WebGL; reports 9 top-level nodes, 17 draw primitives, 12,832 triangles,
   no mesh without UVs, bounds and marker positions exactly as tabulated above.
   Material maps arrive named `textures/<stem>.jpg`, matching the key the runtime
   map cache uses, and the optic glass arrives transparent with `depthWrite`
   false and `userData.glass` true.
5. **Self-containment of the .blend**: reopened from disk, 6 images present and
   all packed at their full byte sizes (264,247 / 298,416 / 380,454 / 283,041 /
   266,344 / 270,366 B), 101 objects, no external references needed.
6. **Render inspection.** All four views were rendered from the actual model and
   looked at. Three defects were found this way and fixed rather than shipped:
   an optic that read as a flag-shaped block, grip and magazine that read as twin
   planks, and webbing/coating patches that read as damage. A clay pass and a
   normal-visualisation pass were used to separate form from texture noise, which
   is how the coplanar-plane defect was isolated.
7. **Determinism**: rebuilding produces a byte-identical GLB.

## Remaining limitations (honest)

- **Not integrated into the game.** No runtime factory, stats, animation
  controller or HANDS/TIMERS value was touched, per scope. Adoption is the
  parent's call; nothing in `public/js` was modified.
- **Hand fit is unverified.** The grip and support palms sit on the contract
  points and the geometry is built around them, but no third-person pose test was
  run, so whether the existing arm IK and glove wrap this specific grip
  convincingly is an assumption, not a measured result.
- **Heat-band mismatch.** The game maps its barrel heat glow across
  `breech -0.32 .. tip -0.598`. On this design the shroud covers 0.300 .. 0.520,
  so only 5.5 cm of bore is exposed and most of that band would fall on the
  shroud rather than on visible bore. It still reads, but the existing glow
  profile is written for the longer exposed barrel of KESTREL.
- **Studio renders are lighter than the game.** The review renders use a bright
  Cycles studio; the runtime has no IBL. `browser-check.html` shows the darker
  in-engine read of the same materials. Both come from the same values; neither
  was retouched.
- **No baked maps.** Base colour only, with scalar metallic/roughness. No baked
  normal, occlusion or roughness maps; no distance LODs; no mobile GPU profiling.
- **Analytic UVs**, not a packed atlas: constant density and no overlapping
  islands, but the tiling is chosen for a mechanical read rather than being
  optimised per part.
- The two `sanity` entries in `validation.json` are intentional and not defects:
  `SHRIKE | indicator` (emissive readout) and `SHRIKE | optic glass` (tinted
  alpha glass) carry no base-colour image by design.
